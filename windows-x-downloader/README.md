# X動画ダウンローダー Windows試作版

Windows 11 x64向け。C# / .NET 10 / WPF。PCから直接Xへアクセスし、投稿内の選択した動画をMP4として保存する。0.2ではアプリ専用のXログインを任意で利用できる。0.2.1は個人用のWindowsインストーラーを追加した。Cloudflare、T-lain Identity、R2、ブラウザ拡張は不要。

## 個人用インストーラー（0.2.1）

`dist/installer/XDownloader-Setup-0.2.1-win-x64.exe` を起動し、日本語の案内に従ってインストールする。既定の配置先は `%LOCALAPPDATA%\Programs\XVideoDownloader`。現在のWindowsユーザー用で、管理者権限と.NETの別途導入は不要。スタートメニューへ登録し、デスクトップのショートカットも選択できる。Windows「設定 → アプリ → インストールされているアプリ」からアンインストールできる。

Xログイン用WebView2 Runtimeが未導入の場合だけ、同梱したMicrosoft公式Evergreen Bootstrapperがネット接続してRuntimeを導入する。導入できなければアプリの配置前に停止し、再試行方法を案内する。セットアップ本体は未署名の個人用であり、PCの設定や入手方法によってWindowsの警告が表示される場合がある。公開配布、コード署名、Microsoft Store公開は行っていない。

更新時はアプリを閉じて新しいセットアップを実行する。起動中はインストール／アンインストールを止め、動画保存を強制終了しない。アプリIDとインストール先を維持して上書き更新する。保存動画、設定、ログイン情報は保持する。旧0.2の開発フォルダーからの起動は、インストール後に終了してショートカットからの起動に切り替える。

PCを買い替えるときは、**セットアップexeをUSBメモリーや個人用バックアップへ保管し、新しいWindows 11 x64 PCで実行する**。アプリの開発フォルダーは不要。動画は別途コピーし、保存先を指定し直す。ログイン情報はWindowsユーザーに紐づいているためコピーせず、新しいPCでXへ再ログインする。旧PCを手放す前にアプリからログアウトする。アンインストールだけでは再インストール用の設定・ログイン情報を消去しない。

セットアップと同名の `.exe.sha256` は整合性確認用。署名や発行者保証の代わりではない。

## 起動

ビルド済みの場合は `dist/XDownloader-0.2.0-final/XDownloader.exe` をダブルクリックする（Build.ps1の標準出力先は `dist/XDownloader`）。`tools` フォルダーも同じ場所に置く。.NETの別途インストールや管理者権限は不要。Xログイン画面には [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) が必要。未署名のローカル試作版であり、一般配布版ではない。

1. `https://x.com/ユーザー名/status/投稿ID` を貼り付けて「解析」。旧twitter.comと共有リンクのクエリにも対応する。
2. 複数動画がある場合は保存対象を選ぶ。画質は最高画質の自動選択、または取得できた画質を指定する。
3. 必要に応じて保存先を変更して「選択した動画を保存」。既定はユーザーフォルダー内のDownloads。
4. 完了後に保存したファイルの場所を表示する。「保存先を開く」でフォルダーを開ける。

キャンセルボタンとEscは解析・保存を中止する。処理中にウィンドウを閉じた場合も子プロセスを停止し、一時ファイルの後片付け後に終了する。同名ファイルは上書きせず連番で保存する。100%表示後も結合・検証が続く場合がある。最高画質はXが配信する画質であり、投稿前の原本を保証しない。

## Xログイン（0.2）

1. 「Xにログイン」を押し、アプリ専用のX公式画面でユーザー名・パスワード・追加認証を完了する。
2. 「ログイン完了」を押す。認証用Cookieの存在を確認して、Windowsの現在のユーザーだけが復号できるDPAPIで保存する。Xによるログインの有効性は、次の投稿解析で確認する。
3. 投稿をもう一度解析する。ログイン変更・ログアウト時には以前の解析結果を解除し、別アカウントの解析をそのまま使わない。
4. 「ログアウト」でアプリに保存したログイン情報を消去する。Xの他端末のセッションを失効させる操作ではない。

パスワードの保存・自動入力は無効。外部サービス経由のログイン（Google/Apple等）は対象外で、Xのユーザー名・パスワードを使う。アプリ内の上位ページ遷移はHTTPSのX/Twitterドメインだけに限定し、外部ウィンドウ、ファイル取得、カメラ等の権限、証明書エラーの迂回を許可しない。Webから.NETへのブリッジは公開しない。既存のChrome/Edge等のプロファイルやCookieは読み取らない。

ログイン画面はアプリ専用のInPrivateプロファイルを使い、閉じたらブラウザープロセスの終了を待ってその領域を削除する。永続保存するCookieは `auth_token`・`ct0`・`twid` の必要なものだけ（Secure、X/Twitterの限定ドメイン、`/` path）に絞る。保持期間は最大30日またはX側のCookie期限の早い方。Windowsユーザーの変更、破損、期限切れでは匿名取得へ勝手に切り替えず、再ログインを案内する。

保存場所は `%LOCALAPPDATA%/XVideoDownloader/auth-v1/session.dpapi`。その親フォルダーと一時領域のACLは現在のWindowsユーザーとSYSTEMだけに制限する。取得エンジンにはCookie本体をコマンドラインで渡さず、処理ごとに作る限定権限の一時ファイルを渡し、子プロセス終了後に成功・失敗・キャンセルのいずれでも削除する。CookieはXへの認証通信に使い、T-lain・Cloudflare・GitHub・ログへ送信しない。現在のWindowsユーザーとして動くプログラムからの読み取りを完全に防ぐ仕組みではない。

アプリはWindowsユーザーごとに1プロセスだけ起動し、処理中のログイン変更・ログアウトを禁止する。取得エンジンとその子プロセスはWindows Job Objectに所属させ、アプリの異常終了時にもOSが停止する。異常終了で残ったアプリ所有の一時認証領域は次回起動時に回収する。保存先、既存の動画、0.1/0.1.1の設定の移行は不要。

## 対応範囲と制約

- 公開投稿のMP4 / HLS、画質選択、投稿内の複数動画から1件選択、進捗・速度・残り時間、キャンセル。
- ログイン後は、そのアカウントが閲覧権限を持つ投稿の取得を試みる。DM、ライブ、DRM、地域制限や閲覧権限の回避は対象外。X側の制限・追加認証・仕様変更で失敗し得る。無制限リトライや、認証失敗後の匿名リトライはしない。
- 「公開されている投稿」と「ログインなしで取得できる投稿」は一致しない。0.1.1では、エンジンが動画情報を取得できなかった場合を通信失敗と分けて案内する。削除、動画なし、非公開・年齢等の閲覧制限のどれかは、このエラーだけで断定しない。
- 取得エンジンは設定ファイル・外部プラグインを読み込まず、X専用extractorだけを使う。投稿内の外部サイト動画へ自動的に広げない。
- メディアは選択した保存先の専用一時フォルダーに取得し、ffprobeで映像streamを確認してから移す。これは完全デコード試験やウイルス検査ではない。
- 保存先を `%LOCALAPPDATA%/XVideoDownloader/settings.json` に記録する。任意のログイン情報は上記の保護領域へ保存する。URL、動画タイトル、取得履歴、エンジンの生ログは保存しない。
- 通常のキャンセル・失敗時には作業用フォルダーを削除する。強制終了・停電・ファイルロック等では保存先の `.xdownloader-*` が残る場合がある。他のプロセスのフォルダーを自動削除しない。
- 解析120秒、保存30分、通信20秒のタイムアウト。保存は同時1件。途中再開、常駐監視、一括取得、アプリ内再生は未実装。

取得する権利のある動画に使用すること。技術的な取得可否とXからの許諾は別であり、X利用規約と投稿者の権利に従う。調査報告で説明した規約上の制約はこの試作で解決するものではない。

## 開発・検証

.NET 10 SDKが必要。Windows PowerShellでこのディレクトリから実行する。

```powershell
.\Verify.ps1
.\Build.ps1
# インストーラー作成（Inno Setupコンパイラーをcacheへ準備する）
.\Build-Installer.ps1
# 既存のインストールと同名ショートカットがないユーザーで実行する
.\Verify-Installer.ps1 -SetupPath .\dist\installer\XDownloader-Setup-0.2.1-win-x64.exe
```

Buildは固定した公式releaseからyt-dlpとFFmpegを取得し、コミット済みSHA-256を照合してから自己完結型アプリを作る。約100MBの取得と.NET publish用の依存取得が初回に必要。依存ファイルはローカルのtools/cache、出力はdistへ置き、Gitには含めない。通常ビルドは既存の検証済みcacheを再利用する。

エンジンを更新する場合は `tools-manifest.json` の公式release URL・version・SHA-256をレビューして更新し、Prepare-Tools.ps1とVerify.ps1を実行して再ビルドする。ダウンロード中の実行ファイルを置き換えない。動作確認前に自動で最新版へ追従しない。

Verifyは外部X・実ユーザーデータ・本番環境を使わない。URL境界、複数動画・画質、エラー分類、保存検証、上書き防止、キャンセルと子プロセス停止、および実WPFイベント経由の解析→保存・キャンセル・入力変更を合成fixtureで試験する。実Xの取得成功を保証する試験とは区別する。0.2では生成した合成CookieでDPAPI暗号化・復元、ACL、期限切れ、改ざん拒否、処理後削除、ログアウトを試験し、実WebView2のInPrivate初期化・Cookie受け渡し・復元・終了時削除もローカルHTMLだけで確認する。

実エンジンがある環境ではCLI引数の互換性に加え、1秒の合成映像・音声をFFmpegで作り、loopback HTTP配信→実yt-dlp取得→ffprobe検証→保存→全体デコードまで試験する。外部ネットワークを使うのは依存の初回準備だけ。実エンジンがない場合はこの2試験を明示的にskipする。

このHTTP fixtureではX用の合成Cookieを実yt-dlpに渡し、別ホストの取得へCookieが送られないことも確認する。0.2のローカル確認はCore 41件・認証22件成功（skipなし）と、WPF／実WebView2試験成功。Coreには、監督プロセスを実際に強制終了して取得エンジンも停止する試験を含む。実アカウントのパスワード入力・二段階認証・対象投稿の取得は本人操作が必要であり、この自動試験の成功とは区別する。

公開用exe自身の `--verify-package` は、隔離した一時領域・ローカルHTML・生成した合成Cookieだけを使って、WebView2の起動とDPAPI／一時Cookie／ログアウトの一巡を試験し終了する。実ユーザーのログイン保存領域には触れない。CIでもpublish後にこの試験を行う。

2026-10-17の初回検証: 39試験成功・skipなし、WPF操作試験成功。別途、X公開投稿1件で動画1本・画質7候補の解析、HLS取得（1,229,442 bytes）、MP4の全体デコードを確認した。検証用の取得ファイルは試験後に削除した。全投稿・全画質・長時間動画の網羅試験ではない。一般配布・コード署名・Microsoft Store公開は行っていない。

このディレクトリは静的サイトの公開対象外であり、Workerのdeployは不要。依存バイナリを含む一般配布前の対応は THIRD-PARTY.md を参照する。

インストーラーのコンパイラーとWebView2 Bootstrapperも `installer/installer-tools.json` のSHA-256およびAuthenticode発行者で検証してから使う。BootstrapperのURLはMicrosoftの更新先リンクのため、将来その内容が変わると初回取得は安全のため失敗する。その場合は公式の署名とバージョンを確認してmanifestを更新する。検証済みcacheがあれば同じファイルを使う。コンパイラーはビルド専用で、完成したセットアップに含めない。

Verify-Installerは実際のセットアップexeを一時的な日本語・空白入りパスへ導入し、エンジンの同一性、ショートカット、アプリ一覧への登録、導入されたexeのオフラインWebView2/DPAPI試験、再インストール、起動中の置換拒否、アンインストール、合成ユーザーファイルの保持を検証して後片付けする。実ユーザーのCookieや動画にはアクセスしない。WebView2導入済み環境での確認であり、未導入PCでMicrosoft Runtime自体を取得する経路は別途実機確認が必要。CIでもこのセットアップ検証を行う。インストーラーexeはGit／Actions artifactへ公開しない。
