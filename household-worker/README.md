# 家計簿

公開先 `/household/`、Worker `t-room-household`、専用D1 `household-db`。機能要件は[設計書](../docs/household-design.md)を参照する。

## 初版

手入力の収入・支出・振替、計算対象／対象外、月別／年別集計、分類・口座・フリーワード検索、自由な口座と内訳、月末資産合計・口座別チャート、CSV出力、バックアップ保存・復元を提供する。予算管理とCSV・PDF・画像からの明細取り込みは含めない。

初期の明細と資産履歴は空。「減価償却」口座の内訳1件だけを0円で用意する。家計明細と口座残高は独立し、一方の操作で他方を増減しない。口座画面で基準日付きの残高を入力し、その履歴から資産推移を自動集計する。マイナス残高に対応する。過去チャートの入力は完成直前の別作業とし、現在残高を変更しない。

## 残高入力と資産推移

口座の残高編集には「残高の基準日」を必須とし、日本時間の今日以前の日を指定する。各口座の`balances`へ日付と内訳を保存し、同じ日の保存は訂正、別の日は履歴追加とする。現在残高の`items`には最も新しい基準日の内訳を保持し、過去日の追加・訂正で現在値を巻き戻さない。保存済み履歴の選択と訂正は口座画面だけで行う。日付・内訳・残高は既存のrevision・冪等操作IDと同じ原子的な更新で確定する。

各月末以前の最新記録を口座ごとに選び、内訳合計を集計する。翌月の記録を前月へ使用しない。入力のない月は直前の記録を繰り越し、最初の記録より前を0円で補わない。基準日未入力の既存口座がある場合は、不完全な資産合計を表示しない。計算はGET `/api/data`の`assetHistory`として返し、定期ジョブや手動の月末確定操作は使わない。当月は今日までの暫定値として表示し、採用元の基準日を記録一覧に表示する。

資産推移は編集者でも閲覧専用とし、月末記録の追加・編集・削除UIと`snapshot.*`・`historical.*`変更操作を廃止する。移行済み・保存済みの月末記録はそのまま保持し、その月の自動計算で上書きしない。過去チャートの口座を今後の口座に接続する場合は、口座編集で`historyId`を一度指定する。名前による自動統合はせず、重複した対応付けや既存対応の付け替えは拒否する。

10月分はマネーフォワードの2026-10-30時点の資産を過去チャートだけへ追加する。`sourceAsOf`に取得対象日を保存し、月末前であることを表示する。9月までと同じく住宅ローン・カード利用残高を除き、口座の現在残高と家計明細は変更しない。11月以降の残高は利用者が入力する。

初期表示は全期間。My Investmentと同じく、1・3・6ヶ月／1・2・3・5・7・10年を記録期間に応じて表示する。最新の月末を終点に、指定月数前の月末も含む（毎月の記録があれば1ヶ月は2点、1年は13点）。資産合計または一口座を選べる。期間や口座の変更は表示だけに反映し、金融データやrevisionを変更しない。

資産推移の開始は2022年6月30日。`0004` migrationはそれより前の月末記録と移行履歴を、非アクティブな復元世代も含めて物理削除する。対象がアクティブ世代にあればrevisionを進め、編集中の旧revisionによる上書きを拒否する。APIとDBの両方で開始月を制限し、古いバックアップからの復活も防ぐ。家計明細の日付・口座残高・分類は変更しない。本番適用時はTime Travelの復旧点、削除件数、保持対象のハッシュ一致を確認する。

チャートは表示された要素の実寸から描画し、非表示中の幅を使用しない。ResizeObserverと表示切り替えで再描画する。金額軸は円・万円・億円・兆円の適切な単位、年月軸は横幅に合わせた間隔とし、文字は12pxを維持する。全期間を含め、表示中の最小値・最大値の外側に変動幅の5%だけ余白を取る。目盛りの丸めで表示範囲を広げず、同額・1件の場合だけ残高の0.05%（最低1円）を上下へ取る。期間・口座・記録の変更で再計算し、ホバーでは軸を動かさない。精密な目盛りは桁を省略せず、必要な横幅を確保する。

マウスのホバーは金額・年月・グラフ上の点だけをプレビューし、下のバーと確定月は動かさない。マウスが外れたら確定月へ戻す。クリック・タップ・横方向のドラッグと、月選択のスライダー・前後ボタン・キーボードは確定月を変更する。正確な残高を円で表示し、前月の記録がある場合だけ前月比を表示する。全月の丸印やTab移動先は作らず、選択点と単独の記録だけに印を付ける。欠損月や口座の未記録は線を切り、0円・日次値・推定前月比を生成しない。

記録一覧は年単位で折りたたみ、初回は最新年を開く。スマートフォンでは記録を縦に並べる。閲覧専用でも期間・口座・月を選べるが、編集・削除はできない。ログアウト時はチャートと選択値も消去する。旧口座との対応付けは口座編集で行い、自動統合しない。

## 認証と共有

既存Security Centerのパスキー、60秒・一回限りhandoff、サービス専用Secret、12時間rolling session、毎回のIdentity／credential／link失効確認、監査を使用する。新しい認証方式・暗号鍵管理・Passwordログインは追加しない。

サービスアカウントは `owner`（田中宏知、編集可能）と `viewer`（共有ページ、全データを閲覧可能）。編集用は既存 `primary-admin` Identityだけが利用できる。閲覧専用の連携は第一管理者が既存の招待・承認・サービス連携手順で明示的に付与する。同じ共有アカウントを複数Identityへ割り当てられる。アカウント名は権限の根拠にしない。

共有用でも検索・集計・書き出しができる。APIは読み取り用と変更用を分け、共有用からの明細・口座・月末残高・分類の変更と復元を403で拒否する。画面でボタンを隠すだけの制御にしない。

## 保存と更新

- `household_accounts`: サービスアカウントとrole・有効状態・session version。バックアップ復元の対象外。
- `household_state`: 現在のデータ世代と全体revision。
- `household_records`: 世代・記録種別・安定したIDごとのJSON。口座（基準日付き残高履歴を含む）、明細、分類、保存済み月末残高、過去チャートを分離する。
- `household_requests`: 操作ID・入力のハッシュ・結果。通信再送を冪等にする。

更新では期待revisionを必須とし、revisionの連番をDB triggerでも検証する。操作IDの記録、revision更新、対象行の変更を一つのD1 batchで確定し、競合は409で全体をロールバックする。別タブの変更は通知し、古い編集の暗黙上書きを防ぐ。

個々の値は整数円。明細20,000件、口座200件・各内訳100件、分類500件、月末／過去記録はそれぞれ3,600件まで。保存するJSON本文の合計は10MiBまでとし、上限では明示的に拒否する。バックアップのアップロードは16MiBまで、画面のファイル選択は12MiBまで。JSON・D1の上限を超えた不完全な保存を成功扱いしない。

## バックアップと復元

形式 `troom-household` v2。日付付き残高履歴と過去口座の対応付けを含む。v1の復元にも対応し、基準日不明の旧残高へ推測の日付を付けない。口座・内訳・明細・分類・月末記録・過去チャートを含め、Identity、認証用アカウント、パスキー、Cookie、Secretは含めない。バックアップから権限を作成しない。

復元前に全レコードの型・ID・参照・標準分類・金額・年月を検証する。新しい非公開世代へ50行ずつ準備し、完了後に期待revisionのCASと操作ID保存を一つのbatchで確定する。同時再送も準備世代を分ける。失敗した準備世代や旧世代はそのままではAPIから見えず、現行世代を削除しない。旧世代の削除や自動整理は初版では行わない。

CSVはUTF-8 BOM付き、金額は収入が正・支出が負。内容・メモ等の文字列で表計算の式が実行されないようにする。

## API

| API | 内容 |
| --- | --- |
| GET `/api/session` | 認証状態・表示名・role |
| POST `/api/passkey/handoff` | 既存パスキー認証の一回限り引き換え |
| POST `/api/logout` | セッション終了 |
| GET `/api/data` | 有効世代のデータとrevision |
| POST `/api/mutate` | `{requestId,expectedRevision,operation,value}` |
| GET `/api/backup` | アプリの全データを書き出す |
| GET `/api/export.csv` | 家計明細のCSV出力 |
| POST `/api/restore` | `{requestId,expectedRevision,backup}` |

変更APIには同一Origin・JSONを要求する。HTTPS、no-store、CSP、画面埋め込み拒否、LINE内ブラウザ制限を使用する。入力値・金融情報・資格情報をログへ出力しない。既存の共通dialogで戻る・Esc・背景・閉じる・未保存入力の保護を統一する。Web自動更新は未保存入力・処理中に延期する。オフラインキャッシュ・PWA manifestは初版に設けない。

## 検証と初回公開

```sh
pnpm run check
pnpm test
# ルートから、合成データとローカルSQLiteだけで実施
node household-worker/test/household.browser.mjs
node tools/verify.mjs --target household --build
```

単体試験は残高と収支の独立、共有用権限、実Security連携、migrationの削除範囲と保持データ、再送・競合、壊れた復元・準備中の失敗・同時復元を検証する。チャートの暦月フィルター、欠損月の前月比、ゼロ・マイナス・大きな値の軸も確認する。ブラウザfixtureは1440px・390px・320pxで、52か月の合成記録を使った初回表示・タブ遷移・リサイズ・期間選択・ホバー中のバー固定・タッチ／キーボード選択・文字の領域内表示・閲覧専用・ログアウト消去を確認する。実端末WebAuthnの操作とは区別する。

初回は専用D1に `0001`〜`0003` を適用し、専用 `SESSION_SECRET` を安全な乱数で新規設定する。既存Secretは上書き・共有しない。Securityのサービス追加migrationは既存データと外部キーを維持し、利用者へのアクセスを自動付与しない。既存のSecurity Centerで第一管理者が編集用・共有用の必要な連携を設定する。

初回のWorker作成・route・D1・Service Bindingの準備は、通常のversion昇格とは別のインフラ手順で行う。既存サービスのrouteを変更しない。コード公開は対象CIが成功したmainを使用し、Securityと家計簿の双方が準備できた後にインデックスへ入口を公開する。切り戻しでは新規D1や記録を削除せず、入口を戻し、サービスを停止または修正版へ進める。
