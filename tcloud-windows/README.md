# T-Cloud Windows

Windows 11 x64向けのHDD同期アプリ。選択したNTFS保存先へ、認可された全原本を順次取得して平文で保持する。初回のパスキー認証後はWindows専用の端末認可で同期を再開し、通常のWeb画面・パスキー設計・ログイン期限は変更しない。

## 利用方法

配布パッケージの `Install.ps1` を実行する。管理者権限や別途の.NET導入は不要。初回だけ空の専用フォルダを選び、パスキーで本人確認する。保存先はNTFSの固定ディスクとして認識される外付けHDD等に対応し、OneDrive等の同期フォルダと重なる場所は拒否する。フォーマットは実行しない。

一覧と名前を先に作り、未閲覧の原本もバックグラウンドで全体取得する。未取得の原本は保存完了後に開き、取得済みの原本はHDDから開く。保存済み本体は自動削除・脱水せず、通信断、アプリ停止、Webセッションの終了後も通常の平文ファイルとして読む・編集する。

- ファイルの追加、名前変更、内容の上書きは、全原本の初回取得を待たずに先にオンラインへ反映する。内容更新前の旧版はT-Cloudオンラインのゴミ箱へ移し、既存の30日保持を適用する。復元時は別名で戻し、最新版も残す。
- 新しいデータはHDD内の既存のT-Cloudフォルダへ保存する。その配下の新規フォルダも同期する。最上位フォルダの新設は、既存の保護方針に従ってWebから行う。
- エクスプローラーの実際の保存先でも「削除」を非表示にし、原本のDelete／Shift+Deleteと同期範囲外への移動を拒否する。オンラインの削除APIは呼ばない。
- 確認済みのWeb削除はHDDへ反映する。一覧から見えなくなっただけでは消さない。未送信の編集は同期範囲外の保全先へ残し、自動再アップロードしない。
- 競合する編集は別名で保全する。Web削除や原本更新と重なった保存は、元の拡張子と元パス情報を付けて保全する。通知領域の「保全した編集を開く」から取り出せる。
- ウィンドウを閉じると通知領域へ移る。「終了」は同期だけを止め、取得済みの原本を残す。Windowsサインイン時の再開はチェックボックスで選べる。

媒体のGUID・シリアル・保存先の実ファイルIDを照合する。ドライブ文字が変わっても同じ媒体を探し、同じ文字に接続された別HDDへ書き込まない。登録済みの同期記録が失われた場合は既存原本を保持して停止し、非空フォルダを勝手に採用しない。

## 認証と保存

初回だけ既存のSecurity→Cloud認証で、承認済みパスキーとPRF envelopeを端末内で利用する。復号用RSA鍵と端末署名鍵は別の非抽出CNGキーにし、PCの登録情報は本人のWindowsアカウントに結び付くDPAPIで保存する。以降は短期のWindows専用アクセストークンを自動更新する。権限・鍵・連携の失効は確認し、失効後はオンライン同期だけを停止する。

原本・動画は端末側で既存のTRC1／AES-GCM形式へ暗号化して送信する。復号鍵、PRF、秘密鍵、平文の動画をCloudflareへ送らない。写真等の軽量な表示情報は既存Webと同じ署名判定・例外規則を使い、動画はこの例外に含めない。HDDには平文の原本・送信用コピー・必要な保全ファイルを置き、鍵は保存しない。

PC側の `device.dat`、`catalog.json`、送信・差し替え・名前変更の再開記録は `%LOCALAPPDATA%\TCloud\Windows` に置く。記録を上書きして別アカウント・別媒体へ流用しない。原本取得・上書き・削除の確定前に再開情報を保存し、応答消失後も同じ操作を安全に照合する。

## 開発・検証

Node.js 24、.NET SDK 10、Windows x64、NTFSとMSVC／CMakeが必要。開発時は `artifacts/native-toolchain` に配置した公式Zig配布物も使える。コンパイラーを自動ダウンロードしない。

```powershell
node tools/verify-tcloud-windows.mjs
```

合成データだけで暗号互換性、CFAPI、削除拒否、物理パスでのShell能力、アップロード・改名・上書き・応答消失・再開・Web削除・保全を検査する。自己完結型パッケージの生成とログインカードの描画も確認する。テストは実ユーザーの原本や実パスキーを使わない。

```powershell
node tools/build-tcloud-windows.mjs
```

`artifacts/distribution/<packageId>/` に `Install.ps1`、ファイルhash付きmanifest、自己完結型のpayloadを生成する。インストーラーは本人用のアプリ保存先へ配置し、既存プロセスの正常終了を待ってから起動する。同期原本や登録情報は削除しない。

Officeの追加実機試験は `dotnet run --project tcloud-windows/tests/TCloud.Sync.Tests --configuration Release -- --compatibility-probe --office`。Excelで保存した値の再読込、ブックを開いたままの送信用コピー、変換後の削除拒否を検査する。Word・PowerPoint実アプリ、実HDDでの初回登録、実際のWindows再起動は、この自動試験の確認済み範囲に含めない。

認証、同期、旧版退避、公開手順は[Windows同期設計](../docs/tcloud-windows-design.md)を正本とする。本番APIの有効化と実HDDの初回登録は、コード・migration・バックアップの確認後に行う。
