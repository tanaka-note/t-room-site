# 請求書管理のゼロ知識暗号化と移行設計

承認済みのパスキーによる通常ログインから、請求書の鍵を端末内で準備・解除する。第一管理者の通常ログインを起点に、全利用者の既存データを暗号化へ切り替える。同じ移行計画で旧バックアップも暗号化して移し替え、復元できることを世代ごとに確かめる。通常利用に必要なSecurity Centerでの追加暗号化設定はゼロとする。[ゼロ知識暗号化の共通設計](passkeys.md#ゼロ知識暗号化の共通設計)に従う。

## 暗号化対象と認可

| 対象 | 保存方法 |
| --- | --- |
| 請求書・支払通知書・入出金 | 取引日、書類種別、分類、金額、摘要、備考、入出金の方向と方法を含め、台帳の内容を暗号化する。 |
| 残高と履歴 | 月初・月末残高、月別集計、過去の基準残高、論理削除済みの内容、入金の旧明細と精算の対応を保全する。財務値、取引日、取引日の月別索引は暗号化する。 |
| 操作履歴 | 金額や変更前後の明細など、財務内容を管理者用の鍵で暗号化する。サーバーには監査に必要な操作種別、操作者と対象のID、操作時刻を保持する。 |
| 認証と同期 | サーバーには既存のアカウント・連携・権限と、認可・競合検出に必要な不透明なレコードID、鍵世代、revision、操作IDを保持する。 |

台帳の鍵は利用者アカウントごとに分ける。一般利用者は本人の台帳を閲覧し、管理者は既存の管理範囲に従って閲覧・更新する。初回の全件移行と中央復旧を実行できるのは第一管理者Identityと請求書ownerの両方を満たすセッションとする。鍵配布とAPIの認可はそれぞれ、現在有効なIdentity、credential、サービス連携、アカウント、権限を照合する。監査の財務内容を一般利用者の台帳鍵で開ける構成は避ける。[請求書APIの現行認可](../../billing-worker/src/index.js)

月初・月末残高は端末で計算する。請求と支払通知の符号、入出金の方向、相殺の扱い、精算へ移行済みの旧入金を二重計上しない判定を現行SQLと照合する。旧基準残高の行も保全し、現行計算への寄与は旧APIの結果との照合で判定する。過去月の更新・削除や別利用者への明細移動では、影響を受ける台帳の該当月以降の暗号化済み残高・索引を更新する。明細、派生残高、監査記録は対象台帳のrevision確認と同じトランザクションで確定する。PDFは端末で復号した画面から出力する。[現行集計と操作履歴](../../billing-worker/src/index.js) · [財務計算の回帰テスト](../../billing-worker/test/performance.test.js)

## 通常ログインと鍵の自動配布

1. 承認済みの既存パスキーで請求書にログインする。同じWebAuthn認証でPRFを要求し、Securityの本人認証済み応答から請求書用の信頼設定を確立する。本人鍵が未登録と確認できた場合に端末内で準備し、登録済みの場合は既存鍵を解除する。
2. 第一管理者は必要なときだけ既存の中央復旧鍵を端末内で解除する。請求書専用の台帳鍵を中央復旧用に封印し、利用可能な公開鍵が確認できた承認済みの受取人にはその台帳鍵を配布する。既存公開鍵を利用する場合も請求書の連携とアカウントを照合し、請求書の鍵を用途別に管理する。
3. 受取人の鍵が未準備でも全件移行を進める。本人の初回ログインで鍵を自動準備し、その後の管理者の通常利用で委譲する。待機中は状態を表示し、配布後は有効なセッション内で利用を再開できるようにする。

PRF出力、秘密鍵、台帳の平文は端末内で扱う。鍵を永続化する場合は暗号化済みの形式か用途を限定した非抽出CryptoKeyを使い、有効セッションとcredential・連携・アカウント・鍵世代に結び付ける。PRF非対応時は対応環境の案内を表示する。権限喪失を検知した場合は平文表示と鍵の参照を破棄し、既に配布済みの鍵への対応は鍵世代の更新で扱う。端末上の信頼設定と署名済みの鍵世代・データrevisionを確認して、古い状態の再提示を拒否する。[日記の通常ログインと中央復旧](diary-encryption.md#通常ログインからの全件移行2026-11-16)

## 現行D1の移行と切替

1. 第一管理者の認可、直近の本人確認、本人鍵・中央復旧鍵の解除を確認する。既存の書き込みを止めて元データを固定し、同時操作が切替を越えて書き込めない条件をDBでも適用する。元のレコードのID・内容・件数と旧APIの月別残高を照合用に記録する。
2. 管理者端末が全利用者の元データを小分けに取得して暗号化する。暗号文の準備、保存、読戻しを段階ごとに記録する。再送は操作IDと保存済み暗号文に結び付け、元の世代・権限・件数が一致するところから再開する。画面に処理段階と件数を表示する。
3. 保存済みの暗号文と鍵情報から実バックアップを作り、隔離DBへ実際に復元する。同じ管理者端末で全件を復号し、固定した元データ、現DBの暗号文、復元DBの結果を照合する。件数・内容・月別残高・鍵世代・署名が一致した時点で、暗号化版への切替、現行D1に残る移行対象の平文の消去、平文書き込みの拒否を原子的に確定する。
4. 切替後は暗号文と復旧用の暗号化済み鍵情報を定期保存する。未対応の旧クライアントの更新を拒否し、切替後の復旧は検証済みの暗号化世代から行う。切替前に失敗した場合は固定した原本と移行の進捗を保全する。

既存の暗号化対応に合わせ、Backup Workerのスキーマ基準、エクスポート許可リスト、復元定義を同じ変更で更新する。実バックアップの復元照合前に平文原本を整理しない。[共通の切替条件](passkeys.md#既存データの移行と完了確認) · [バックアップのスキーマ検証](../../backup-worker/README.md#対象と保持)

## 旧バックアップの移し替え

1. 本番切替前に、請求書の旧形式と現行形式の日次・月次および手動で保管した世代を棚卸しする。世代ごとに保存時点、マニフェストと参照part、件数を記録する。日次・月次で共有するpartは参照先まで照合する。
2. 現行D1の移行と同じ作業期間に、第一管理者の端末で旧バックアップのマニフェストと本文を読み取り、保存時点と復元に必要なメタデータを含めて端末で暗号化する。アーカイブ鍵は請求書の復旧用に封印し、世代を保持したまま別の非公開保存先へ保存する。大きい世代は分割し、保存済みの分から再開できるようにする。旧世代の変換は通常利用者の初期表示から切り離す。
3. 保存先から暗号文を読み戻し、管理者端末で復旧鍵を使って復号する。各世代を隔離DBへ実際に復元し、当該世代の元データと件数・内容・残高を照合する。検証済みの世代を整理候補に登録し、未移行・失敗・参照が残る原本は保全する。
4. 平文原本の整理を確定する前に、保存した暗号化世代で対象をすべて復旧できることと、残すマニフェストが原本partを参照していないことを確認する。D1 Time Travelは現行D1の平文消去を確認した時点と実際の保持期限を記録し、期限満了まで平文履歴が残存しているものとして扱う。

家計簿のアーカイブの暗号化と、旧・現行形式を隔離復元する仕組みを参照する。完了記録には現行D1の切替、旧世代の暗号化・実復元、平文原本の整理、Time Travelの期限満了を個別に記載する。[R2の保持と参照確認](../../backup-worker/README.md#d1-exportによる保存) · [家計簿のアーカイブ](../../backup-worker/tools/household-archive.mjs) · [隔離復元](../../backup-worker/tools/restore-isolated.mjs) · [D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/)

## パスキー認証後の表示と先読み

- 認証後、請求書画面と暗号化モジュールの準備、本人鍵の解除、初期表示の暗号文取得のうち、依存しない処理を並行する。保護データの取得と描画はそれぞれ有効セッションと利用者の範囲を照合する。通常の再訪では移行・復元用資材を初期表示の経路から外す。
- 既存の初期集計同梱を踏まえ、選択中の利用者・当月の暗号化済み一覧と残高を優先する。取引年月を含む索引は端末で復号し、サーバーへの取得指定は不透明な識別子を使う。初回描画後に隣接月を少量ずつ先読みし、利用者や月の切替では今の表示要求を優先する。
- 再訪時は暗号文と暗号化済み索引を、容量上限付きで端末に保存して再利用する。現在の権限、利用者、鍵世代、revisionを照合してから描画する。ログアウト・失効・切替に伴って不要な取得を中断し、遅れて完了した復号結果を破棄する。

測定はパスキー操作、サービスのセッション発行、鍵解除・初期通信、当月の初回描画を分ける。PCと実スマートフォンで初回・再訪・月切替を現行版と比較し、中央値・95パーセンタイル・転送量を記録する。合成データの計測と実機の計測は別に記録する。[請求書の現行測定](../history/billing-performance-20261024.md) · [日記の段階表示](diary-encryption.md#通常ログインの段階的な表示2026-11-17)

## 受入確認

- 既存のPRF対応パスキーで一度ログインし、追加設定なしで閲覧できること。新端末、本人鍵の初回準備、既存鍵による事前配布、未準備者への後日配布、セッション再開を確認する。
- 第一管理者が利用者の初回ログインを待たずに全件を移行できること。通信切断、保存応答の喪失、同時操作で重複や欠損が生じず、権限・世代が不一致のときは切替を停止すること。
- 一般利用者が他の台帳や管理者用の監査内容へアクセスできず、失効後に暗号文取得・表示・更新が拒否されること。
- 書類と入出金の登録・訂正・削除・移動、月初と月末残高、年またぎ、相殺、PDF、操作履歴が現行結果と一致すること。
- 切替時の実バックアップと旧日次・月次を暗号化保存先から隔離復元し、全件照合に通ること。旧世代の整理対象と残存するTime Travelの保護期間を記録できること。
- 当月表示を優先でき、隣接月の先読みと端末キャッシュ再利用が現在の認可と世代を守ること。実機の初回・再訪で現行版との表示時間・転送量の比較を記録すること。
